## Сохранение наблюдений

`record_observation()` в `app/services.py` блокирует строку прогона через
`SELECT … FOR UPDATE` и проверяет, что прогон активен. `finish_run()` использует
ту же блокировку. Пары `(type_name, field_name)` разрешаются в идентификаторы
полей снимка этого прогона. Неизвестное поле отклоняется до вставки. При ошибке
анализа допускается сохранить диагностическое наблюдение без связей с полями.

В `observed_requests` сохраняются метаданные операции и HTTP-ответа, признаки
наличия `data` и GraphQL-ошибок, длительность, код ошибки и опциональный хеш
запроса. Тело запроса, переменные и секретные заголовки в эту таблицу не
попадают. В `request_field_usage` сохраняется по одной связи для каждой
уникальной пары «наблюдение — поле». Составной первичный ключ закрепляет эту
уникальность. Наблюдение и связи фиксируются одним коммитом транзакции.

## Расчёт покрытия

`get_run_graph()` передаёт снимок и идентификатор прогона в `get_graph()`.
`hits` — число наблюдений прогона с успешным анализом и
`response_has_data = true`, связанных с полем. GraphQL-ошибки в ответе с
`data` не исключают наблюдение. Поле покрыто при `hits > 0`. Повтор операции
увеличивает `hits`, сохраняя количество уникальных покрытых полей.
Field Coverage равен числу покрытых полей, делённому на число учитываемых полей
и умноженному на 100. Результат округляется до двух знаков.

**Дефект.** Парсер сохраняет поля `OBJECT` и `INTERFACE`, а общая статистика
графа суммирует поля обоих видов. Поля интерфейса увеличивают знаменатель и,
если у них есть `hits`, числитель. По ТЗ общая метрика должна включать
пользовательские поля типов `OBJECT`, в том числе корневых `Query` и
`Mutation`. Поля интерфейса, поля входных типов, служебные поля и
introspection-типы исключаются. Например, при покрытии `Query.user` и
`User.id` наличие непокрытого `Node.id` даёт текущие 2/3 вместо ожидаемых 2/2.

## PostgreSQL, миграции и тесты

ORM-модель содержит семь таблиц — `graphql_services`, `schema_snapshots`,
`schema_types`, `schema_fields`, `test_runs`, `observed_requests` и
`request_field_usage`. Внешние ключи связывают снимки, прогоны, наблюдения и
поля. Частичный уникальный индекс ограничивает число активных прогонов одним
на снимок.

Для тестов использована локальная `.venv` с Python 3.13.5 и зависимостями
проекта, включая `.[test]`. `pip check` прошёл. В отдельной базе
`graphql_coverage_test` на PostgreSQL 18.6 команда `alembic upgrade head`
применила `20261113_initial`. Проверены статус `head` и наличие семи таблиц
приложения. Тест использовал `TEST_DATABASE_URL` и внешнюю откатываемую
транзакцию с SAVEPOINT. После прогона в `observed_requests` было 0 строк.

| Прогон | Прошло | Упало | Пропущено | Исключено фильтром |
| --- | ---: | ---: | ---: | ---: |
| `python -m pytest -m "not integration" -ra` | 6 | 0 | 0 | 1 |
| Интеграционный прогон PostgreSQL | 1 | 0 | 0 | 6 |

Unit/API-тесты проверяют разбор SDL, нормализацию пробелов для хеша, обработку
невалидного SDL, имена ORM-таблиц, маршруты OpenAPI и `/health`.
Интеграционный тест проверяет повторный импорт снимка, покрытие 3/5 = 60%,
дедупликацию поля внутри операции, рост `hits` при повторной операции и отказ
в записи после завершения прогона. Его схема не содержит интерфейсов.

`docker compose config --quiet` прошёл. Docker Engine был недоступен, поэтому
запуск сервиса `postgres:16-alpine` через Compose и миграция на PostgreSQL 16
пока не проверены.
