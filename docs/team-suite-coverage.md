# Coverage по командам и наборам

При регистрации попытки через `POST /api/runs/{runId}/tests` runner может
передать `teamKey` и `suiteKey`. Это стабильные строки длиной до 128 символов.
У попытки один первичный набор и одна команда-владелец теста. Ключи задаются
при создании и входят в проверку повторной регистрации того же UUID.
Изменение ключей требует новой попытки. Старые клиенты продолжают работать.

Python SDK принимает аргументы `team_key` и `suite_key` у `TestExecution`.
Плагин pytest читает маркеры `@pytest.mark.coverage_team("checkout")` и
`@pytest.mark.coverage_suite("smoke")`. Значения по умолчанию задаются через
`COVERAGE_TEAM_KEY` и `COVERAGE_SUITE_KEY`. Playwright принимает `teamKey`
и `suiteKey` в настройках fixture и reporter, с теми же переменными окружения.
Используйте одинаковые настройки fixture и reporter, включая тесты без fixture.

## Чтение

`GET /api/runs/{runId}/test-coverage/groups?groupBy=suite` возвращает
страницу групп. `groupBy=team` группирует по команде. Фильтры `teamKey`,
`suiteKey`, `unassignedTeam=true`, `unassignedSuite=true` комбинируются через
AND. Нельзя одновременно задать ключ и unassigned для одной категории.
`limit` ограничен 500, `offset` задаёт смещение, `X-Total-Count` — число групп.
Порядок стабильный, группа с `key=null` идёт первой. Показывайте её как
«Без группы». Пустой прогон возвращает пустой список.

Каждая группа содержит `totalTests` (уникальные framework + testId),
`totalExecutions` (попытки), `requestCount`, `selectedFieldCount`,
`coveredFieldCount`, `observedFieldCount`, `totalFields`, `coveragePercent`.
Тесты без обращений включаются в счётчики тестов и попыток.
Обращения без testExecutionId включаются в «Без группы» с нулём попыток.
Неизвестные поля ответа не считаются observed. Счётчик
`unavailableEvidenceRequestCount` включает обращения без evidence или с
неполными evidence. Нулевой observedFieldCount сам по себе не доказывает
отсутствие поля в ответе.

`GET /api/runs/{runId}/test-coverage/fields?suiteKey=smoke` возвращает поля
группы с теми же фильтрами, пагинацией и форматом счётчиков, что и поля
отдельной попытки. Чтобы показать непокрытые поля, сопоставьте результат
с графом снимка. На `GET /api/runs/{runId}/tests` также доступны фильтры групп,
а ответы создания, списка и детализации попытки дополнены ключами.

## Подсчёт и доступ

Процент равен числу уникальных OBJECT-полей с учтённым выбранным обращением
группы, делённому на общее число OBJECT-полей снимка прогона. Учитывается
успешный анализ с response_has_data=true. Повторные попытки и обращения
увеличивают свои счётчики, но не число уникальных полей. Интерфейсные поля
в selected/observed доступны, однако в процент OBJECT coverage не входят.
Проценты групп не складываются.

Оба новых маршрута используют правила журнала: analyst/operator с service
grant либо admin/CLI. Запись ключей использует существующий защищённый
маршрут регистрации попытки. Ключи описывают маркировку runner и не дают
пользователю дополнительных прав.

Миграция `20261125_test_groups` добавляет nullable-колонки и индексы по
runId + ключу. Исторические попытки сохраняются без маркировки. Downgrade
удаляет только колонки групп и индексы.
